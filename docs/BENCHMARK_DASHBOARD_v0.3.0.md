## 8. v0.2.0 대비 개선

### 주요 성능 개선

| 영역 | v0.2.0 | v0.3.0 | 개선율 |
|------|--------|--------|--------|
| 기본 토큰화 | ~6 µs | ~1.8 µs | **3x 빠름** |
| 중간 텍스트 | ~42 µs | ~11.5 µs | **3.6x 빠름** |
| 긴 텍스트 | ~135 µs | ~41 µs | **3.3x 빠름** |

### 개선 원인

1. **Viterbi 알고리즘 최적화**
   - 불필요한 메모리 할당 제거
   - 더 나은 캐시 지역성

2. **메모리 최적화**
   - PosTagInterner: 품사 태그 문자열 중복 제거
   - FeatureCache: Feature 문자열 캐싱
   - String interning으로 메모리 사용량 감소

3. **Lattice 재사용**
   - 연속 분석 시 Lattice 재사용
   - 할당 오버헤드 최소화

## 9. 권장 사용 패턴

### 고성능 사용법

```rust
// 1. 토크나이저 재사용 (권장)
let mut tokenizer = Tokenizer::new()?;
for text in texts {
    let tokens = tokenizer.tokenize(text);
}

// 2. 스트리밍 처리 (대용량 파일)
let mut stream = StreamingTokenizer::new(tokenizer);
for chunk in file.chunks(8192) {
    stream.process_chunk(chunk);
}

// 3. 목적에 맞는 API 사용
let nouns = tokenizer.nouns(text);  // 명사만 필요시
let wakati = tokenizer.wakati(text); // 표면형만 필요시
```

### 성능 팁

1. **토크나이저를 한 번 생성하고 재사용**하세요
2. **대용량 파일은 청크 단위로 스트리밍 처리**하세요 (5x 처리량 향상)
3. **목적에 맞는 분석 모드를 선택**하세요 (wakati, nouns 등)
4. **배치 처리 시 단일 토크나이저 사용**이 효율적입니다
